# Agent Note: Windows 残留安装修复

Status: implemented

[English](2026-08-18-windows-residual-install-repair.md) | 中文

## 问题

用户可能手动删除已经安装的 Desktop 目录，也可能遇到旧版卸载未完成，但当前用户的安装与卸载注册表项仍然保留。下一次 NSIS 安装会尝试调用已经缺失或不可用的旧卸载器。Electron Builder 会把多次失败显示成通用的“应用无法关闭”对话框，因此即使所有 Desktop 进程已经停止，继续重试也无法修复安装。

## 决策

Windows 安装器会先关闭应用及其拥有的进程树，再检查已注册安装。私有安装器退出参数只作为非阻塞通知启动，因为只负责传递信号的 Electron 次实例在送达请求后仍可能保持存活；固定等待和进程树终止负责有界关闭。只有注册路径与本次选择的安装目录完全一致，或以默认专属 `DeepSeek Harness` 目录结尾时，缺少应用可执行文件、缺少卸载器或注册版本属于任意 `0.1.0-rc.*` 预览版，才会被识别为可修复安装。安装器随后会在 Electron Builder 执行旧版本卸载步骤前，删除该应用目录和两条失效卸载命令。普通载荷解压会重新创建目录和完整卸载注册信息。Profile、工作区、凭据和插件数据都位于应用目录之外。

## 验证

打包配置覆盖固定了专属目录检查、不完整文件识别、预览版本族识别、残留删除和卸载命令清理。Windows 原生生命周期工作流会安装并启动打包 Host，在运行中的预览版上再次执行同一安装器，启动替换后的应用并完成运行中卸载；随后再单独保留注册表、删除应用目录并验证残留修复。

## 考虑过的替代方案

**要求每位用户手动删除目录或运行 `taskkill`。** 否决，因为安装器能够安全识别和修复该状态，不应要求用户执行技术恢复步骤。

**无条件删除注册表中的任意安装路径。** 否决，因为损坏或异常的注册路径不能授权递归删除专属产品目录之外的位置。

**不删除残留，只覆盖文件。** 否决，因为被占用、不兼容或只删除了一部分的旧文件可能在覆盖后继续存在，使新载荷保持不一致。

## 后果

损坏的当前用户预览安装可以直接通过普通引导安装器恢复，无需任务管理器、PowerShell 或手动清理 AppData。修复会有意删除专属应用目录内的全部文件；它不会删除用户 Profile 数据，但用户自行放进程序目录的文件不会保留。
